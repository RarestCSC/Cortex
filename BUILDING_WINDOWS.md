# Building Cortex for Windows

This guide covers the unsigned Windows x64 installer. It is intentionally
separate from the Linux build and does not change any Linux defaults.

## Scope

- Output: `Cortex-<version> Setup.exe` (Squirrel, per-user install)
- Architecture: x64
- Signing: none (self-use)
- Local inference: **not built** on Windows. API providers, Code Mode, MCP,
  keyring and the ACP server are included.
- The "Local Inference" settings tab is hidden automatically because the
  backend only advertises that capability when the `local-inference` feature
  is enabled.

## Prerequisites

- Windows 10/11 x64 or Windows Server 2022
- Visual Studio 2022 Build Tools (MSVC v143 + Windows SDK)
- Rust 1.99.0 (`rust-toolchain.toml`)
- Node.js 24.10+ and pnpm 10.30+
- CMake 3.20+
- NASM (required by `aws-lc-sys`)
- Git and Python 3
- A short checkout path such as `C:\cortex`

GitHub Actions `windows-latest` already provides Visual Studio, CMake and
Python. The workflow only installs NASM explicitly.

## Local build

```powershell
cd C:\cortex

# 1. Backend without local inference
cargo build --release -p cortex-cli --bin cortex `
  --no-default-features `
  --features "portable-default,code-mode,system-keyring,online-model-meta"

.\target\release\cortex.exe --version
.\target\release\cortex.exe serve --help

# 2. Stage the backend where Electron expects it
Copy-Item .\target\release\cortex.exe .\ui\desktop\src\bin\cortex.exe -Force

# 3. UI dependencies
cd .\ui
pnpm install --frozen-lockfile

# 4. Windows runtime files (uv.exe/uvx.exe, npx.cmd, jbang.cmd)
cd .\desktop
$env:ELECTRON_PLATFORM = "win32"
node .\scripts\prepare-platform-binaries.js

# 5. Build and package
pnpm run build-acp-client
pnpm run i18n:compile
$env:ELECTRON_ARCH = "x64"
pnpm exec electron-forge make `
  --platform win32 `
  --arch x64 `
  --targets=@electron-forge/maker-squirrel
```

Output:

```text
ui\desktop\out\make\squirrel.windows\x64\Cortex-1.54.0 Setup.exe
```

## GitHub Actions

The workflow is manual-only:

1. GitHub -> Actions -> **Windows build** -> **Run workflow**.
2. Wait for the job to finish (first run is usually 60-90 minutes).
3. Download the `cortex-windows-x64-setup` artifact.
4. Verify the SHA256 file before running the installer.

The workflow builds the backend with `--no-default-features` and does not touch
the Linux workflow or the default Cargo features.

## Unsigned installer

The installer is not code-signed. Expected behavior:

- SmartScreen shows "Windows protected your PC" on first run. Use
  "More info" -> "Run anyway".
- Downloaded artifacts may carry Mark-of-the-Web. If Windows blocks the file,
  right-click -> Properties -> Unblock, or run:

  ```powershell
  Get-ChildItem .\Cortex-1.54.0*Setup.exe | Unblock-File
  ```

- The publisher is shown as unknown in "Apps & features".
- Antivirus false positives are possible. Add an exclusion only if you trust
  the artifact.
- No integrity/authenticity guarantee for third parties. For self-use, verify
  the SHA256 generated by the workflow.

## Smoke test

On a clean Windows VM without Rust/Node/Visual Studio:

1. Install `Setup.exe`.
2. Confirm the Start Menu shortcut starts Cortex.
3. Confirm `resources\bin\cortex.exe --version` reports `1.54.0`.
4. Configure an API provider and send a message.
5. Test a `npx` or `uvx` based MCP extension.
6. Test Code Mode.
7. Confirm the "Local Inference" settings tab is absent.
8. Test `cortex://recipe?...` after starting the app once.
9. Uninstall from "Apps & features"; user data in `%APPDATA%\Cortex` and
   `%LOCALAPPDATA%\cortex` is intentionally left behind.

## Troubleshooting

- **`aws-lc-sys` fails**: install NASM and ensure it is on `PATH`.
- **`v8` download fails**: GitHub must be reachable. Do not interrupt the
  build: the v8 build script removes its cached static library before
  re-downloading.
- **Packaged app cannot start the backend**: verify
  `ui\desktop\src\bin\cortex.exe` exists before `electron-forge make`.
  `prepare-platform-binaries.js` now fails early if it is missing.
- **Node/npx MCP extensions fail**: `npx.cmd` may download a portable Node.js
  on first use; a network connection is required unless Node 22+ is installed.
- **Add/Remove Programs icon is the Electron default**: Squirrel's `iconUrl`
  must be a public HTTP(S) URL. The `Setup.exe` icon itself comes from
  `setupIcon`.

## Linux isolation

Only Windows-specific paths are changed:

- `.github/workflows/windows-build.yml` is manual-only.
- `maker-squirrel` is restricted to `platforms: ['win32']`.
- The Windows feature set is passed only on the Windows command line.
- The Windows branch of `prepare-platform-binaries.js` is the only changed
  branch.
- `Cargo.toml`, `.cargo/config.toml`, `Justfile` and the Linux makers are
  untouched.
